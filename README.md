# Meeting Scribe

Zoom、Google Meet、Teams などのオンライン会議をローカルで文字起こしする macOS アプリです。macOS 15 以降の Apple Silicon を対象にしています。

## 仕様

- ScreenCaptureKit でマイクと Mac のシステム音声を別々に取得し、「自分」「相手」の2ラベルで表示します。
- 録音中は Kotoba-Whisper v2 Q5_0（約538 MB）で発話区間ごとにリアルタイム認識します。終了後は、Whisper large-v3（約3.1 GB）で再処理するか、リアルタイム結果を使うかを選べます。どちらも whisper.cpp の Metal 対応 `whisper-cli` を使い、会議音声と文字起こしを外部サービスへ送信しません。
- 録音中は16 kHz mono PCM16 のマイク音声とシステム音声を話者別に一時保存します。録音終了後、5分単位の音声チャンクを順番に再認識し、成功した話者の結果を最終結果として使います。片方の処理に失敗した場合は、その話者だけリアルタイム結果を保持します。
- バッチでは多言語Whisper large-v3の長文逐次デコードを使います。公開日本語評価の複数セットでKotoba-Whisper v2より低い文字誤り率が報告されていますが、会議音声での改善幅は録音内容に依存します。時刻付きセグメントへチャンク開始時刻を加え、録音全体の時間軸に戻します。
- 結果は時刻、話者ラベル付きの UTF-8 テキストとして保存できます。生音声は処理が完了すると一時ファイルから削除されます。録音中は両話者合計で約230 MB/時の一時ディスク容量を使います。音声全体をメモリへ読み込まず、保存書き込み待ちも10秒分に制限します。
- Zoom/Meet/Teams の会議らしいタイトルを持つウィンドウを確認し、開始・終了前に確認ダイアログを出します。完全な会議状態検出ではなく、手動操作が基本です。

## ビルド・インストール・起動

対象は macOS 15 以降の Apple Silicon です。必要なものは Xcode Command Line Tools（Swift コンパイラ、macOS SDK、Git）、CMake、Homebrew です。Command Line Tools が未導入なら、まずターミナルで次を実行してインストールを完了してください。

```sh
xcode-select -p >/dev/null 2>&1 || xcode-select --install
```

Homebrew も未導入の場合は[公式手順](https://brew.sh/)で先にインストールしてください。Homebrew と Command Line Tools の準備ができたら、プロジェクトのルートディレクトリーで次を実行します。

```sh
brew install cmake
./scripts/build-whisper-cli.sh
./scripts/build-app.sh
./scripts/install-app.sh
open "/Applications/Meeting Scribe.app"
```

`build-whisper-cli.sh` は whisper.cpp を取得してビルドし、`build-app.sh` は arm64 の `.app` を `dist/Meeting Scribe.app` に作ります。whisper.cpp の取得にはネットワーク接続が必要です。SDKが古くビルドできない場合は、Xcode Command Line Toolsを更新してください。

`install-app.sh` はビルド済みアプリの署名を検証してから、標準の `/Applications` にインストールまたは更新します。既定の動作では `sudo` を使いません。書き込み権限がない場合はユーザー用の Applications フォルダーにインストールできます。

```sh
./scripts/install-app.sh "$HOME/Applications"
open "$HOME/Applications/Meeting Scribe.app"
```

更新するときはアプリを終了し、`build-whisper-cli.sh`（whisper.cpp を新規取得または再ビルドするとき）と `build-app.sh` を実行してから `install-app.sh` を再実行してください。ユーザー用フォルダーにインストールした場合は、更新時も `./scripts/install-app.sh "$HOME/Applications"` のように同じ導入先を指定します。インストール先の既存アプリは、新しい `.app` の署名確認後に置き換わります。モデルはユーザーの Application Support 内にあるため、アプリ更新で再取得されません。

Apple Development などの署名 identity がある場合は `MEETING_SCRIBE_CODESIGN_IDENTITY` に identity 名を指定してビルドできます。省略時は ad-hoc 署名です。ad-hoc 署名のアプリは公証されません。再ビルド後に macOS が録音権限を再度求める場合は、システム設定で Meeting Scribe にマイクと「画面収録とシステムオーディオ録音」のアクセスを許可してください。

`.app`にはwhisper.cpp実行ファイルと必要なライブラリが含まれ、初回起動時に実行ファイルを選択する必要はありません。録音には Kotoba-Whisper v2 Q5_0 の「モデルを取得」が必要です。終了後の再処理を使う場合は「高精度モデルを取得」から Whisper large-v3 も取得してください。large-v3は約3.1 GBあり、推論時に数GBの追加メモリを使います。モデルは `~/Library/Application Support/MeetingScribe/Models/` に置かれます。両モデルの取得後はネットワークを切っても文字起こしできます。large-v3未取得でも録音できますが、終了後はリアルタイム結果を使う選択肢のみ利用できます。

## 録音後のバッチ処理

録音中のリアルタイム結果は暫定表示です。録音を止めた後、リアルタイム推論が終わると選択ダイアログを表示します。「Whisper large-v3で再処理」を選ぶと、一時保存したマイク音声とシステム音声をそれぞれ5分単位で再入力します。「リアルタイム結果を使う」を選ぶと、バッチ推論を実行せず、録音後の一時音声を削除してリアルタイム結果を保存できます。話者ごとの音声を混ぜず、「自分」=マイク、「相手」=システム音声のラベルを維持します。バッチ結果には whisper.cpp のセグメント時刻と元チャンクの開始時刻を加算します。

バッチ処理中は、現在の話者・チャンク内の認識進捗をプログレスバーで表示します。残り時間は whisper.cpp が出す5%刻みの進捗から実行速度を見積もり、処理の進行に合わせて更新します。モデル読み込み中や進捗が長く止まった場合は、残り時間を推定中と表示します。表示時間は推定値で、音声内容やMacの負荷によって変わります。

Whisper large-v3 はKotoba-Whisper v2より大きく、認識速度より精度を優先するバッチ用モデルです。whisper.cpp / Metalの既存経路で実行し、長時間録音でも音声全体をRAMへ展開しないよう5分ごとに推論します。公開評価ではCommonVoice 8 JapaneseとJSUT Basic 5000でKotoba v2を上回り、ReazonSpeechではKotoba v2の方が良い結果です。データセットや会議内容によって優劣は変わるため、実際の会議での精度向上を保証するものではありません。バッチ処理に失敗した話者については、既に表示済みのリアルタイム結果を最終結果として残します。

2026年10月3日に、YouTubeの約10分のシステム音声を録音し、提供されたYouTube字幕との文字差を比較しました。空白・句読点を除去して比べた差分率は、この録音ではlarge-v3が約20〜23%、Kotoba Q5_0が約62%でした。これは自動字幕との比較値であり、逐語の正解に対するCERではありません。また、Kotobaのコマンドライン実行はCPU、アプリ内large-v3はMetalだったため、処理速度は比較していません。この結果を踏まえてバッチにはlarge-v3を維持します。

無音対策としてwhisper.cppのSilero VADとno-speechしきい値変更も同じ録音で評価しました。2つ目の5分チャンクをlarge-v3・CPUで処理したとき、1,924文字の自動字幕との文字差分率はVADなし21.83%、控えめなVAD設定（speech threshold 0.35、最小発話100 ms、最小無音300 ms、padding 200 ms）27.13%、whisper.cppの標準VAD設定28.48%でした。VADは末尾の誤挿入を抑えましたが、発話の文字も多く失い、全体の一致度が下がったため、バッチにはVADを常時適用していません。no-speechしきい値を0.3に変更した出力も標準設定と同一で、誤挿入は残りました。実時間側の無音判定は固定RMSしきい値を使います。今回の評価はシステム音声だけなので、マイクの雑音や小声での検出は別途確認が必要です。

一時音声はシステム一時フォルダー内の Meeting Scribe 専用ディレクトリーに保存し、ディレクトリーは所有者のみ読み書きできます。通常はバッチ処理後に削除し、アプリが異常終了して残った7日以上前のディレクトリーも起動時に回収します。バッチ推論と音声書き込みはUIスレッド外で動きます。処理中は結果の保存と次の録音を無効にしますが、アプリ画面は応答を続けます。

停止後の「音声診断」には、録音経過時間と話者ごとの入力時間範囲、WAVチャンクごとの実時間、WAVへ書き込んだサンプル量、重複時刻のために除いたサンプル量が表示されます。音声時刻が250msを超えて逆行した場合や、重複除外が累計5秒かつ受信サンプルの0.5%を超えた場合は、バッチ音声を破棄してリアルタイム結果を残します。さらに、リアルタイム発話の時間範囲が保存済みWAVの時間範囲に含まれない場合、その話者は丸ごとリアルタイム結果へfallbackします。途中チャンクの欠落や末尾の切れもこの照合で検出します。

音声範囲が揃っていても、バッチ認識の品質が崩れる場合があります。リアルタイム結果があるのにバッチ結果が空の場合、バッチがリアルタイムより大幅に短い場合（リアルタイム40文字以上かつバッチがその25%未満）、または6文字以上の同一句の反復がバッチ文字数の半分以上を占め、リアルタイムに比べて大幅に増えている場合、その話者はリアルタイム結果へfallbackします。判定はセグメント内・セグメント間の反復を調べ、リアルタイムで0回ならバッチ2回以上、リアルタイムで1回以上ならバッチが `max(3, 2 × リアルタイム回数 + 1)` 回以上の場合を反復増加と見なします。定型句だけを一律に削除するのではなく、反復とリアルタイム結果の両方を見て判定します。話者単位での保守的なfallbackなので、その話者の正しいバッチ改善も取り消す場合があります。音声診断と完了状態にfallback理由を表示します。この判定は明らかな空結果・内容崩壊・反復への対策であり、すべての認識誤りを検出する保証はありません。

初回の録音開始時に macOS の「プライバシーとセキュリティ」で「画面収録とシステムオーディオ録音」と「マイク」のアクセスを Meeting Scribe に許可してください。アプリは開始時にmacOSのマイク許可を要求します。ScreenCaptureKit のシステム音声取得は画面収録権限を必要とします。開始時にTCCの拒否エラーが出る場合は、システム設定で両方のアクセスを許可してからアプリを再起動してください。

開発用ビルドは ad-hoc 署名です。Apple DTSの説明のとおり、再ビルド後は画面収録のTCC許可が新しいコード署名に引き継がれないことがあります。その場合は最終ビルドを起動し、システム設定で Meeting Scribe の画面収録許可を付け直してからアプリを再起動してください。安定した開発運用では Apple Development 証明書で署名してください。

## 話者ラベルと制約

「自分」はローカルのマイク入力、「相手」は Mac のシステム出力音声です。システム音声を再生する Zoom / Meet / Teams 以外のアプリ音声も混ざります。ブラウザーの場合、Meet のタブだけでなくブラウザーからの音声が対象になる場合があります。

ヘッドホンを使ってください。スピーカー音がマイクへ回り込むと、相手の発話が「自分」にも重複する場合があります。マイクの取得は会議アプリのミュート状態とは連動しません。録音中はローカルマイクに入った音声を取り込みます。

会議検知はウィンドウ名に基づくヒューリスティックです。会議開始・終了を正しく判定できない場合があるため、誤検知時は「後で」を選び、必要に応じて手動で開始・終了してください。無音状態だけでは自動終了しません。
